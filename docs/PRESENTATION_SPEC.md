# 演出仕様 — 2系統の演出エンジン

Status: 仕様固定（2026-11-14、オーナー決定）。エンジン自体は未実装で、現行の表示は暫定実装（後述）。
素材の一覧と状態は `data/materials.json`（素材レジストリ）を正とする。

## 原則: 素材と演出の意味を分離する

素材は「何が・いつ・どこで起きたか」の記録であり、演出は「それをどう見せるか」である。
素材ごとに **イベントID（EVT-*）・発生日・出典・演出タイプ** を持たせれば、素材が増えても
ゲーム本体の構造は変えず、内部の抽選・進行処理は共通化できる。

## エンジンA: 全文テキストスクロール型（text_scroll）

- 対象: ニュース記事、SNS投稿、掲示板レス。
- 表示: 原文テキストを液晶内で **下から上へ連続スクロール** させる。記事・投稿・掲示板レスは同じ表示エンジンを使う。
- 原文は改変しない（後知恵で書き換えない）。改行・>>参照は保持する。
- 例:
  - ベインEXIT報道（MAT-NEWS-20260709-BAIN、EVT-010）
  - AI相場への説教ポスト（MAT-SNS-20260621-TOP、EVT-008）
  - Yahoo!ファイナンス掲示板の投稿群（MAT-BOARD-285A）

## エンジンB: 原本画像表示型（original_image）

- 対象: 公式IR・決算資料（適時開示PDF、決算短信など）。
- 表示: PDFのページを画像化し、**原本の紙面そのまま** を液晶に表示する。ゆっくり拡大・移動（パン／ズーム）させたり、複数ページを切り替えたりする。
- IRの本文をテキスト化してスクロールさせることはしない。無機質な決算資料の紙面が突然液晶全面に現れること自体が演出である。
- 例: 決算短信、株式分割のお知らせ、主要株主である筆頭株主の異動に関するお知らせ、設備投資（サンディスクとの投資計画）発表。
- 素材化パイプライン（2026-11-14にパイロットで確立）:
  1. 公式IRニュース一覧の各リンクからPDFの実URL（ssl4.eir-parts.net のTDnet文書）を特定する。
  2. PDFをダウンロードする（PDF自体はリポジトリに保管しない。出典として `pdf_url` をレジストリに記録する）。
  3. `scripts/convert_ir_pdf.py <pdf> <素材ID>` でページ画像化する: **JPEG・150dpi・品質85、原本無加工**（切り抜き・テキスト化・再組版をしない）→ `materials/ir/<素材ID>/page-XX.jpg`。
  4. `scripts/wrap_ir_images_svg.py <素材ID>` でSVGラッパーを生成する: `page-XX.svg`。現在のGitHub push経路はテキスト専用でバイナリを送れないため、同一のJPEGを base64 で埋め込んだSVG（テキスト）として格納する。ブラウザでは通常の画像として表示され、埋め込みJPEGはバイト単位で原本と同一（生成時にハッシュ照合）。ゲームが読み込むのは `.svg` の方で、レジストリの `images` も `.svg` を指す。
  5. レジストリの `images` / `pages` / `pdf_url` を更新し、`status` を `stored_image` にする。
- パイロット実績（2026-11-14）: 7件・44ページを取得済み（上場のお知らせ／株式分割／2027年3月期Q1決算短信18頁／筆頭株主異動／サンディスク投資計画／初配当・株主還元方針／同Q2決算短信18頁）。
- **全件取得完了（2026-11-14）**: IR 78件のうち **69件・351ページ** を画像化して格納済み（status=stored_image）。内訳: 適時開示・決算短信等のPDF 53件、有報・半期報告書3件は冒頭10ページのみ（オーナー決定、全文ページ数は `pages_total` に記録）、ウェブ記事16件は下記の方法で取得。残り9件は画像化対象外として確定: 文書自体が存在しない告知8件（status=no_document。決算発表予定のお知らせ等、一覧上のテキスト告知のみ）、CG報告書1件（status=render_blocked。PDF自体は正常だが埋め込みフォントをローカル変換機で描画できず文字が抜けるため保留。ブラウザ側レンダリングでの代替取得が候補）。
- 格納形式（2026-11-14、オーナー決定）: GitHub Pagesでそのまま表示できるよう、画像はSVGラッパー形式でリポジトリに格納する（上記パイプライン手順4）。

### ウェブ記事の取得方法（PDFが存在しない記事）

- 当初方針は「フルページスクリーンショットで画像化」だったが、ブラウザ自動化環境では撮影したスクリーンショットを画像ファイルとして取り出す手段がなかった（表示確認のみ可能で保存不可）ため、**記事ページをブラウザの「PDFとして保存」でキャプチャし、そのPDFを上記パイプラインでページ画像化する**方式に変更した（2026-11-14、オーナーへ報告済み）。
- レジストリでは `capture_method: web_page_print_pdf` とし、記事URLを `article_url` に記録する。印刷レイアウトの紙面になるため、ブラウザ画面そのままの見た目とは異なる。画面そのままの見た目が必要になった場合は、ユーザーのChromeで撮影したスクリーンショットへの差し替えが可能。

## ステージ設計（2026-11-14、オーナー決定）

- **ステージの背景はYahoo!ファイナンス掲示板のスクロール**（エンジンA）が担う。掲示板は日常の空気そのもので、日付が進むと投稿の温度が変わり、ステージの質感が変わる。
- **IR（エンジンB）は示唆・ステージ移行の演出に使う**。IRの紙面が出ること自体が「内部で何か起きている」合図になる（北斗のステージ固有演出の位置づけ）。
- **示唆の真偽は市場感応度で決める（2026-11-14、オーナー決定）**: そのIRが本示唆かガセ示唆かは、開示の内容ではなく **IRが出た翌営業日の終値の変化** で決める。市場が実際に反応した開示だけが本物、という実データ準拠の格付け。レジストリの各IRに `market_sensitivity`（next_day / next_day_return_pct / grade）を実測して付与済み。格付けは grade = high（|翌日変化| ≥ 10%、17件）／mid（5〜10%、24件）／low（< 5%、34件＝ガセ寄り）／unknown（データ末尾で翌日なし、3件）。方向（上昇／下落）も保持し、上位移行示唆か転落示唆かを分ける。ゲーム内では、IR演出が出た翌ゲームの終値表示そのものが判定になる。
- **IRは日単位で管理する（2026-11-14、オーナー決定）**: 同日に複数のIRがある場合、演出・格付けの単位は個別の開示ではなく **その日一式** とする。市場感応度が同日内では全件同一になる（市場は一式に反応する）こととも整合する。IR演出では、その日の筆頭開示（優先順位: EVT連動 > 決算短信 > ページ数最大）の紙面を表示し、他の開示はタイトルを「〇〇 & 〇〇、〇〇」の形で並べて示す。日単位の索引は `data/ir_days.json`（全50日、各日に headline_id / item_ids / titles / market_sensitivity を保持）。
- **IR日の演出カテゴリ（2026-11-14、オーナー提案・機械判定の初版）**: 各IR日を、発表前5営業日の変化（pre5）・当日変化（day0）・翌日変化（next）から次のカテゴリに分類し、`data/ir_days.json` の `reaction.category` に保持する。判定は機械的で、内容の解釈はしない。
  - **悪材料出尽くし**: next ≥ +5% かつ（day0 < 0 または pre5 ≤ -5%）。下げた末の反発。例：2026-07-17 訴訟の陪審評決（pre5 -32.3%、day0 -16.1%、next +17.2%）。
  - **市場織り込み済み**: pre5 ≥ +8% かつ |next| < 5%。先行して上がり、発表では動かない。例：2025-10-30 統合報告書（pre5 +47.9%、next -0.7%）、2026-05-25 格付BBB-格上げ（pre5 +27.2%、next -4.6%）。
  - **無風**: |next| < 5% かつ |day0| < 5% で、上の2つに該当しない。開示はあったが市場は無反応。
  - **素直な反応**: |next| ≥ 5% で、上のどれにも該当しない。例：2025-11-13 決算（next -23.0%）。
  - 50日の内訳（初版）: 無風18／素直な反応15／市場織り込み済み9／悪材料出尽くし7／unknown1（データ末尾）。

## 同じイベントでも系統は素材で決まる

2026-07-31の決算短信はIR（エンジンB）。2026-06-21のAI相場説教ポストはSNS（エンジンA）。
イベントIDが同じでも、素材の出所と性質によって系統が決まる。系統はイベントではなく素材の属性である。

## 素材レジストリ（data/materials.json）

各素材は次の項目を持つ:

| 項目 | 内容 |
|---|---|
| `id` | 素材ID。`MAT-<種別>-<日付>-<短縮名>`（掲示板コレクション等は日付なしも可） |
| `kind` | `news` / `sns` / `board` / `ir` |
| `presentation` | `text_scroll`（エンジンA）または `original_image`（エンジンB） |
| `event_id` | 関連するイベント候補ID（EVT-*）。無ければ null |
| `date` | 発生日（報道日・投稿日・発表日。種類は素材ごとに注記） |
| `title` | 素材の題名（IRは公式タイトル） |
| `source` | 出典 |
| `content_path` | リポジトリ内の素材本体の場所（テキスト素材・掲示板） |
| `images` | エンジンB用のページ画像のパス一覧（未取得なら空） |
| `status` | `stored_text` / `stored_normalized` / `metadata_only`（メタデータのみ・画像未取得）など |
| `suggestion` | 演出示唆（任意。採用済み仕様と混同しない） |
